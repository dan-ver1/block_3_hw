# Домашнє завдання 3: Weekly Learning Health Report

Я зібрав у n8n звіт про навчальну активність для 15 `enrollments`. Через PostgreSQL я отримую агреговані дані, у двох Code-вузлах визначаю статуси й рахую метрики. Gemini формує короткий управлінський підсумок; результат я записую в Google Sheets.

## Як працює workflow

```text
Manual Trigger ────┐
                   ├→ PostgreSQL → Code: статуси → Code: метрики → Gemini → Google Sheets
Schedule Trigger ──┘
```

У SQL я групую записи `weekly_activity` за `enrollment_id`. Для кожного запису я рахую переглянуті хвилини, середній `quiz_score`, кількість спроб пройти тест та активних тижнів. У першому Code-вузлі я застосовую правила нижче. У другому рахую показники для звіту. Я передаю Gemini один набір підсумкових метрик і роблю один виклик моделі на звіт.

## Правила статусів

У Code-вузлі я перевіряю умови в цьому порядку:

1. **`inactive`**: `last_active_week <= 1`. У вибірці немає запису про продовження навчання після першого тижня. За цим правилом не можна встановити, чи студент активний зараз.
2. **`needs_attention`**: активність після першого тижня є, але `active_weeks < 5`, або середній перегляд за активний тиждень менший за 30 хвилин, або `avg_quiz_score < 70`.
3. **`healthy`**: жодна з попередніх умов не спрацювала. Запис має щонайменше 5 активних тижнів, не менше 30 хвилин перегляду за активний тиждень і середній бал quiz від 70.

Я обрав пороги для цього ДЗ. Вони не є навчальними нормативами. Gemini не бере участі у визначенні статусу.

## Результат тесту

| Показник | Значення |
| --- | ---: |
| Проаналізовано `enrollments` | 15 |
| `healthy` | 3 |
| `needs_attention` | 7 |
| `inactive` | 5 |
| Середній `quiz_score` | 83,4 |

Я налаштував вузол Google Sheets на додавання рядка з полями `run_date`, `n_enrollments`, `healthy_count`, `needs_attention_count`, `inactive_count`, `avg_quiz_score` і `summary`. Повторні тести створили кілька рядків з датою `2026-10-11`. Ці рядки показують окремі запуски однієї демонстраційної вибірки.

## Бонус: запуск раз на тиждень

Я налаштував Schedule Trigger на понеділок о 09:00 за `Europe/Kyiv` та опублікував workflow. Я перевірив ручну гілку та гілку Schedule Trigger окремими тестовими запусками. Перший запуск за календарем ще не перевіряв. У призначений час локальний n8n має працювати.
